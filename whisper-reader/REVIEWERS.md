# Build instructions for add-on reviewers

This add-on's submitted package is **generated**: TypeScript sources are
type-stripped, bundled and minified. This file is the build recipe required
alongside the source archive.

## What generates what

| | |
|---|---|
| Language | TypeScript, compiled to JavaScript |
| Bundler | Vite (via WXT), 25 source modules into 5 output scripts |
| Minifier | Vite's built-in minifier (enabled by WXT for production) |
| Manifest | Generated by WXT from `wxt.config.ts` |
| Icons | Generated by `scripts/make-icons.mjs` into `public/icon/*.png` |
| Template engine | **None.** No Svelte, Handlebars or similar is used |

Nothing is fetched at build time beyond the npm registry, and the extension
has **zero runtime dependencies** — no third-party code ships inside it.

## Environment

The submitted package was built with:

- **Node.js 22.17.1**
- **npm 10.9.2**
- Windows 11 (the build is not platform-specific; Linux and macOS produce the
  same output)

Exact dependency versions are pinned in `package-lock.json`; use `npm ci` so
they are installed verbatim.

## Steps

```bash
npm ci
```

```bash
npm run build:firefox
```

The reviewable output is written to `.output/firefox-mv3/`. That directory's
contents are exactly what the submitted `.zip` contains.

For the Chrome build instead, run `npm run build` and compare
`.output/chrome-mv3/`. The two differ only in the manifest's `background` key —
Chrome MV3 uses a service worker, Firefox MV3 an event page.

## Reproducibility

The build is deterministic. To confirm, this repository includes a checker that
builds twice and compares every output file byte for byte:

```bash
node scripts/check-reproducible.mjs firefox
```

Expected output:

```
Reproducible: all 12 files identical across builds.
```

## Verifying behaviour

The project carries 177 unit tests covering text extraction, sentence
segmentation, the transport state machine, speech-rate quantization, panel
placement and resume positions. WXT's source archive excludes `*.test.ts` files, so they are not in
this bundle; they run with `npm test` in the full repository.

Nothing in the test suite affects the built output — it is not part of the
build pipeline, and `npm run build:firefox` does not invoke it.

## Permissions rationale

| Permission | Why |
|---|---|
| `activeTab` | The reader is injected only when the user clicks the toolbar icon, presses a command hotkey, or uses the context menu |
| `scripting` | To perform that on-demand injection |
| `storage` | Preferences (`sync`); per-page reading positions, per-voice capability verdicts, the speech-rate measurement and the first-run flag (`local`) |
| `contextMenus` | "Read this page" / "Read selection" entries |

There are **no `host_permissions` at install and no optional host permissions.**
The extension has no standing access to any site.

The add-on makes **no network requests of any kind**. Speech comes from the
browser's own `speechSynthesis` API; all processing is local. No analytics, no
accounts, no remote code.
